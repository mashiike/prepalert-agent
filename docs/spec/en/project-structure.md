# Project Structure

## Overview

A prepalert-agent project uses the directory specified by `--project-dir` (default: `.`) as its root.

## Directory Layout

```
<project-dir>/
├── prepalert.yaml          # Project configuration + shared instructions for the Agent
├── .mcp.json               # MCP server configuration
├── references/             # Static documents the Agent can reference (optional)
│   └── *.md
├── runbooks/               # Runbook files (required)
│   └── **/*.md
├── logs/                   # Operation logs (auto-generated, .gitignore recommended)
│   └── {timestamp}-{id}.jsonl
└── sessions/               # Session records (auto-generated, .gitignore recommended)
    └── YYYY/MM/DD/         # Date partitioning
        └── {session-id}/
            ├── metadata.json       # Session metadata (status, createdAt)
            ├── transcript.jsonl    # Agent conversation transcript
            ├── report.md           # Session Report (generated by the Agent via create_report)
            ├── output.md           # Agent's final response text (serve mode)
            ├── artifacts/          # Auxiliary files (generated by the Agent via create_artifact)
            │   └── {filename}
            └── runbooks/           # Per-runbook reports (auto-saved by the harness)
                └── {runbook-id}/
                    └── {tool-use-id}/
                        └── report.md
```

## Role of Each File

### `prepalert.yaml`

Describes the overall project configuration and shared instructions for the Agent. Field names use camelCase. See [project-config.md](./project-config.md) for details.

### `.mcp.json`

Configuration for the MCP servers used by the Agent. Uses the same format as Claude Code's `.mcp.json` and is passed directly to the Agent SDK. Can be shared with Claude Code (the path can be changed via `mcpConfig`).

```json
{
  "mcpServers": {
    "server-name": {
      "command": "...",
      "args": ["..."],
      "env": { "KEY": "VALUE" }
    }
  }
}
```

Supported transports: `stdio`, `sse`, `http` (Streamable HTTP)

### `references/`

A directory for placing static documents that the Agent can reference during investigation. Use it for service architecture diagrams, supplementary operational procedures, and similar materials. The Agent can read these files using the Read tool. The directory path is not managed via configuration; instead, specify the path directly in instructions.

### `runbooks/`

A directory for storing Runbook files. Similar in structure to Claude Code skills (`SKILL.md`), consisting of YAML frontmatter + Markdown body. Unlike skills, runbooks are always executed as independent sub-agents. They can be freely organized into subdirectories. `.md` files are loaded recursively. See [runbook.md](./runbook.md) for details.

### `logs/`

A directory for storing operation logs. One JSON Lines file is created per process startup. HTTP request processing status, Agent execution start/completion, errors, etc. are recorded as structured JSON. The path can be changed via the `logsDir` setting (default: `logs`).

### `sessions/`

A directory for storing Agent execution session records. For each Agent execution (webhook request or interactive session), a subdirectory with a session ID is created, and `transcript.jsonl` (Agent conversation transcript) is saved within it. In `serve` mode, the Agent's final response is also saved as `output.md`. The path can be changed via the `sessionsDir` setting (default: `sessions`).

## CLI

### Common Options

| Option | Description | Default |
|---|---|---|
| `--project-dir <dir>` | Path to the project directory | `.` |
| `--log-level <level>` | Log level (`debug` \| `info` \| `warn` \| `error`) | `info` |

`--log-level` can also be set via the environment variable `PREPALERT_LOG_LEVEL` (CLI flag takes precedence).

**Output behavior:**

| Mode | stderr | File | stdout |
|---|---|---|---|
| `run` (interactive) | warn and above | JSONL | Agent response text |
| `run -p` | All JSONL at or above the specified level | JSONL | Final response text only |
| `serve` | All JSONL at or above the specified level | JSONL | — (saved to `sessions/{id}/output.md`) |

In interactive mode, `--interactive-log-level` can be used to specify the log level independently (falls back to `--log-level` when not specified).

### Subcommands

### `run` (default)

The default command. Also invoked when no subcommand is specified.

#### Interactive mode: `prepalert-agent` / `prepalert-agent run`

1. Starts the Agent SDK query in AsyncIterable (streaming input) mode. MCP server connections begin in the background
2. Displays a `>` prompt via readline and waits for user input
3. Retrieves and caches MCP server connection status via the `system/init` message
4. Delegates to runbook sub-agents or the Explore agent as directed by the user, and investigates using MCP tools
5. Exits on `exit` or Ctrl+D

**Built-in commands:**

| Command | Description | Requires query |
|---|---|---|
| `/help` | Display command list | No |
| `/mcp` | Display MCP server connection status. Shows configuration info only when query is not started | No |
| `/mcp test` | Run a connection test against the project's MCP servers. Attempts reconnect for pending/failed servers | Lazy start |
| `/status` | Display project configuration and account information | Lazy start |
| `/reset` | Reset TotalCost and turn count counters | No |
| `exit` / `/exit` | End session | No |

**Permission:** Specified via the `-m` / `--interactive-permission-mode` flag (default: `default`). Can also be set via the environment variable `PREPALERT_PERMISSION_MODE`.

| Mode | Behavior |
|---|---|
| `default` | Prompts for confirmation via readline in the `canUseTool` callback. `(y)es` / `(n)o` / `(a)lways` |
| `auto` | Automatically determined by the model classifier |
| `acceptEdits` | File edits are automatically approved; all others require confirmation |
| `dontAsk` | Only `allowedTools` are permitted; all others are denied. No confirmation prompts |

#### Headless mode: `prepalert-agent -p "<prompt>"` / `prepalert-agent -p -`

1. Uses the `-p` argument as the prompt. When `-p -` is specified, reads the full text from stdin
2. Starts the Agent SDK query in string prompt (single-turn) mode
3. After execution completes, outputs the final response text to stdout and exits (JSONL logs go to stderr)

**Permission:** Fixed to `dontAsk` mode. Only tools listed in `allowedTools` can be executed. The default includes Read-type tools + all MCP servers.

### `serve`

Starts a webhook server.

1. Starts an HTTP server with `Bun.serve()`
2. `GET /health` — Health check. Returns `{ "status": "idle" | "busy", "activeRequests": <number> }`
3. Routes requests per path based on the `serve.webhooks` configuration
4. Authentication check (none / basic / oidc)
5. Constructs the prompt as `headerPrompt + markdown output instruction + "\n\n" + request body` (markdown instruction is automatically appended)
6. Executes the Agent in the same headless mode as `run -p`
7. Saves the Agent's response to `sessions/{session-id}/output.md`
8. `serve.syncMode: false` (default) -> Returns 202 Accepted immediately; the Agent runs in the background
9. `serve.syncMode: true` -> Waits for the Agent to complete, then returns 200 OK
10. In ECS environments, task protection is automatically enabled during async mode (`serve.ecsTaskProtection: auto`)

**Reserved paths:** `/`, `/index.html`, and paths starting with `/api/` cannot be used for webhooks (configuring them causes an error at server startup).

**Permission:** Same headless mode as `run -p` (`dontAsk` + `allowedTools`).

### `init`

Project initialization (scaffolding). Generates `prepalert.yaml`, `.mcp.json`, `runbooks/example/`, and `.gitignore`. No AI required. See [init.md](./init.md) for details.

### `skills`

Manages skill files provided by prepalert-agent for Claude Code or similar tools. Subcommands: `list`, `install`, `update`, `uninstall`, `status`. Installation scope can be `project` (`.claude/skills/`) or `user` (`~/.claude/skills/`). No AI required. See [install-skills.md](./install-skills.md) for details.
